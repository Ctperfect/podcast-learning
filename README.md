# 播客学习稿 · Podcast Learning

**把专业知识写成闭眼也能跟上的中文讲稿。**

给一个知识点、一份笔记或一篇材料，就能得到可以直接朗读的稿子。听完试着用自己的话讲清核心，再拿它判断一个新例子。

[快速开始](#快速开始) · [看一份长稿](examples/http-cache.txt) · [查看技能规则](SKILL.md)

## 快速开始

在想使用该技能的 Codex 项目目录运行这条命令。

```sh
git clone https://github.com/Ctperfect/podcast-learning.git .agents/skills/podcast-learning
```

也可以下载仓库 ZIP，将 `SKILL.md` 和 `references/` 放进项目的 `.agents/skills/podcast-learning/` 目录。

在该项目的新对话里输入下面这句，试着把一个概念做成播客讲稿。

```text
$podcast-learning 把「接口的幂等性」做成一集我能闭眼听的播客学习稿。
```

## 选一种讲法

| 档位 | 适合谁 | 怎么讲 |
| --- | --- | --- |
| 大白话档 | 对这个主题缺少相关基础的听众 | 点题后用熟悉的场景补背景，再引入准确的专业术语 |
| 常规档 | 已经有相关基础的听众 | 用熟悉的术语直接讲机制、判断和适用边界 |

每份稿只用一档，两档共用同一个学习目标。优先采用本次指定的档位或听众基础，其次是已确认的个人默认档，两者都没有时用大白话档。

给懂 HTTP 的同事写稿时，可以指定听众基础、讲解档位和文件格式。

```text
$podcast-learning 给做过后端的同事系统讲一遍 HTTP 缓存的命中、过期和重新验证。用常规档，输出一份 .txt。
```

## 一集怎么讲

1. 用专业讲解的口吻直接点题，说清要记住什么，再按顺序报出几个要点。
2. 沿着要点讲原因、步骤和适用条件。换例子、改条件或用段间过渡，把同一组重点反复带回来。
3. 结尾把开篇的要点变成问题，请听众先复述，再用一个新例子判断并想想理由。留一句过渡，然后对答案。
4. 问答后按开篇顺序逐点总结，给听众一句下次能用的判断方法。

通常以十分钟左右为参考，按知识点的难度调整。主题很宽时，先给出一个具体切口。想系统听一遍时，多个小问题会用口播过渡串成一份长稿。

写完会做一遍朗读润色，删掉空话、模板转场和客套，再对照原稿核对术语、数字、因果和适用条件。要点的重复用来带路、帮助判断和回顾。普通稿可以直接复制朗读，长稿或指定文件时交付一份 UTF-8 纯文本。播放工具由你选。

## 记下自己的听讲习惯

想把某种讲法留给以后，可以让技能整理成个人偏好。

```text
$podcast-learning 帮我记下我的听讲习惯。我通常有基础，默认用常规档。讲到重点时，用一道小题带我回想。
```

技能会先给你看拟保存的条目和位置，经你确认后才写入专属文件夹。只想改这篇稿时，说「这次」即可。 [个人偏好说明](references/listener-preferences.md)

## 朗读样稿

《HTTP 缓存的命中、过期和重新验证》沿着一层共享代理讲清请求怎么走，最后换成公交站点列表，让听众自己判断下一次请求会读到哪一份正文。 [打开纯文本样稿](examples/http-cache.txt)

样稿按 HTTP 标准讲解缓存行为。 [缓存规则](https://www.rfc-editor.org/rfc/rfc9111.html) · [条件请求](https://www.rfc-editor.org/rfc/rfc9110.html#section-13) · [过期期间后台验证](https://www.rfc-editor.org/rfc/rfc5861.html#section-3)
